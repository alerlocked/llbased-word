# 装配工艺文件验收标准（extract 版 v1）

> 每次代码改动 + 生成后，按此验收。2026-07-10 用户钦定，基于 `assembly_process_template.json` + `exp-generation-debugging` + 全单电缆装配规程样例。
> ⚠ 核心原则：**工序从用户上传文件动态 extract，不存在预设工序清单**。测试文件的工序数（如 12）只是举例，不是标准。

## 一、整体：11 章节，固定顺序，封面 PDF-only

```
G1a 封面(PDF-only) → G4a 工艺文件目录 → G5a 引用文件目录 → G10a 专用工艺装备明细表
→ B12a 专用工具量具明细表 → G12a 主要材料消耗定额 → G14a 辅助材料消耗定额
→ G19a 工艺流程图 → G18a 配套明细表 → G22a 工艺过程卡 → G25a 装配工艺卡片
```

## 二、骨架：G19a extract 工序数驱动一切

- **G19a 工艺流程图先行**（Phase 1），`extract_process_steps` 从**用户上传文件的"工艺流程图"章节**提取工序序列。每次上传不同文件 → 不同工序。**没有"固定工序"**。
- **G18a / G22a / G25a（Phase 2）行数 = 这次 extract 出的工序数**（每工序一行/一卡，错位即不合格）
- **G4a/G5a/G10a/B12a/G12a/G14a（Phase 3）从 G25a 装配内容反推**（derive 强节点，不能空）

## 三、各章节内容标准

| 章节 | 该长什么样 |
|------|-----------|
| G1a 封面 | 元数据（产品工号/密级/工艺文件编号/名称/组件代号名称/编制单位/册数），编辑器不可见、仅 PDF 渲染 |
| G4a 目录 | 本文件自身章节目录（序号/文件名称/编号/页数） |
| G5a 引用目录 | 装配工序提到的参考设计文件/标准（序号/代号/名称/页数） |
| G10a 工装明细 | 从 G25a 专用仪器/工装归纳（编号/名称/类别/数量/用于组件） |
| B12a 工具量具 | 左栏工具 / 右栏量具（从 G25a 设备/量具/检验归纳） |
| G12a 主材料定额 | 零件/材料牌号规格/单位/定额/净重（13列） |
| G14a 辅材定额 | 从 G25a 辅材列归纳（名称/单位/单套定额） |
| G19a 流程图 | **从上传文件 extract 的工序有序列表**（全文档脊梁，每次不同） |
| G18a 配套明细 | 全部零件组件（代号/名称/每装配件数量/总计/来源） |
| **G22a 过程卡** | 每工序一行，**step_desc = 工序名短词直填**（如"装前准备"/"安装密封圈"），**不展开**；车间/工序号/工序名称(钳)/设备/工装/工时 |
| **G25a 装配卡** | 每工序一卡，**content = 详实操作**（100-200字/工序，1.1/1.2 分步，操作+参数+辅材+检验点）；辅助材料/专用仪器仪表/工时 + **检验工序行**(step_name=检验，总量≤工序数) + 开头说明(适用范围) |

## 四、内容铁律（违反即不合格）

1. **源驱动零臆造**：内容来自原文 extract，原文缺→triples 兜底，都无→留空"待补"，**绝不编**
2. **参数忠实原文**：力矩等数值照原文（如 M5螺钉 3.6±0.4N·m），不杜撰
3. **会签/审核栏剔除**：会签/审核/批准/校对/签名/更改单号是文件管理制度、非工艺内容，注入 LLM 的原文不应含
4. **colspan 展开**：表格 colspan/rowspan 网格展开，避免列错位/文本被吞
5. **G22a 抄 / G25a 整理 不混**：G22a step_desc 抄工序名短词；G25a content 整理工步为详实操作
6. **检验=工序行**：检验不单独成列，生成检验工序行，总量 ≤ 操作工序数
7. **行数对齐**：G18a/G22a/G25a 行数 = G19a extract 的工序数

## 五、验收检查清单（每次生成后逐项过）

- [ ] 11 章节齐全、顺序对
- [ ] 后端日志 `chapter_indexes_count > 0`（文档已索引，非无源生成）
- [ ] G19a 工序 = extract 出的真实工序（日志 `phase_output_captured process_flow_steps step_count=N`，N=这次上传文件的实际工序数）
- [ ] G18a/G22a/G25a 行数 = G19a 工序数
- [ ] G22a step_desc 是工序名短词、非空非臆造（日志有 `g22a_process_card_steps_injected`，无 `g22a_no_doc_dir_fallback`）
- [ ] G25a content 详实（100+字/工序、分步、含参数），检验行 ≤ 操作行
- [ ] G4a/G5a/G10a/B12a/G12a/G14a 从 G25a 反推、非空（日志 `derive_strong_applied` 各章 rows>0）
- [ ] 无会签/审核栏
- [ ] 参数与原文一致、无臆造
- [ ] 后端日志无 `derive_strong_failed` / 无空章节

## 附：生成"没到位"先查的 3 个信号

1. `chapter_indexes_count=0` → 文档没索引（上传链路断 / 缓存没清），全无源生成
2. `derive_strong_failed` → derive 强节点 import/上游问题，列表章节空
3. `g22a_no_doc_dir_fallback` → G22a process_card_steps 没注入，step_desc 退化给 LLM

详见 `NTM-wiki/projects/localknowledgebase-word/experience/exp-source-driven-fix.md`。
