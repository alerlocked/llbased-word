# 麒麟工艺文件系统 — 本地部署指南

## 架构

```
麒麟笔记本 (192.168.13.101)                300I Duo 服务器 (192.168.13.153)
┌──────────────────────────────┐            ┌──────────────────────────────────┐
│  前端  React :3000           │            │  Docker: mindie-qwen3-30b-a3b    │
│  后端  FastAPI :8000         │ ─网线直连→ │    Qwen3-30B-A3B :1028 (LLM)    │
│  MinerU pipeline (CPU调度)   │            │  Docker: mindie-mineru-vlm       │
│  conda env: craftdoc         │            │    MinerU2.5-Pro :1040 (VLM)    │
└──────────────────────────────┘            └──────────────────────────────────┘
```

- 无网环境，全部本地，不连云端
- LLM 文本推理 → Qwen3-30B-A3B，跑在 NPU chips 4-7
- PDF 解析 → MinerU pipeline (CPU 调度) + VLM 推理走 NPU chips 0-1
- 两台机器网线直连，同一网段 192.168.13.0/24

## 一、网络连接

两台机器通过网线直连，同一网段：

```bash
# 确认麒麟 IP 为 192.168.13.101
ip addr show eno1 | grep "inet "

# ping 模型服务器
ping 192.168.13.153
```

如果需要改 IP：
```bash
sudo nmcli con mod '有线连接 1' ipv4.addresses 192.168.13.101/24
sudo nmcli con mod '有线连接 1' ipv4.method manual
sudo nmcli con up '有线连接 1'
```

## 二、300I Duo 服务器 — 启动模型

### 2.1 首次：传模型文件到服务器

模型文件较大（30B 约 57G，VLM 约 2.5G），传输需要时间：

```bash
# 从麒麟笔记本执行
scp -r ~/models/Qwen3-30B-A3B root@192.168.13.153:/home/data/
scp -r ~/models/MinerU2.5-Pro-2604-1.2B root@192.168.13.153:/home/data/

# 部署脚本
scp deploy/mindie/run-*.sh root@192.168.13.153:/root/mindie-deploy/
```

### 2.2 首次：加载 Docker 镜像

```bash
ssh root@192.168.13.153
docker load -i ~/mindie-image.tar   # ~18GB
```

### 2.3 启动模型

```bash
ssh root@192.168.13.153
cd /root/mindie-deploy
chmod +x run-qwen3-30b-a3b.sh run-mineru-vlm.sh

# 启动 LLM (全部文本任务)
./run-qwen3-30b-a3b.sh          # chips 4-7, port 1028
./run-qwen3-30b-a3b.sh logs     # 等待 "Daemon start success!"

# 启动 VLM (PDF 解析，必须)
./run-mineru-vlm.sh             # chips 0-1, port 1040
./run-mineru-vlm.sh logs
```

**执行流程**（每个脚本相同）：

1. **创建容器** — `--net=host --privileged`（NPU IPC 需要完整 host 访问）
2. **Patch 配置** — 读取容器内默认 config.json，只覆盖端口、模型路径、NPU 设备 ID
3. **启动 daemon** — source 环境变量 → `ASCEND_RT_VISIBLE_DEVICES` 限制芯片范围 → 拉起 daemon
4. **加载权重** — 自动进行，等 `Daemon start success!` 即就绪

> 脚本采用「patch 默认配置」策略，不做完全覆盖。仓库中的 `config-2.2rc1-*.json` 仅供参数参考，**不会被脚本使用**。

### 2.4 确认模型就绪

```bash
# 看日志
./run-qwen3-30b-a3b.sh logs     # 等待 "Daemon start success!"
./run-mineru-vlm.sh logs

# 测试接口（在服务器上）
./run-qwen3-30b-a3b.sh test     # 应返回模型列表和推理结果
./run-mineru-vlm.sh test
```

### 2.5 检查防火墙（关键步骤）

模型容器用 `--net=host`，MindIE 绑定 `0.0.0.0`，但服务器防火墙可能拦截端口。

```bash
# 在服务器上检查
firewall-cmd --state

# 如果显示 "running"，开放端口：
firewall-cmd --add-port=1028/tcp --permanent
firewall-cmd --add-port=1040/tcp --permanent
firewall-cmd --reload

# 或者临时关闭防火墙（测试用）：
systemctl stop firewalld
```

## 三、麒麟笔记本 — 配置后端

编辑 `~/project/localknowledgebase-word/backend/.env`：

```bash
# ============ LLM (Qwen3-30B-A3B, port 1028) ============
DASHSCOPE_API_KEY=not-needed
DASHSCOPE_BASE_URL=http://192.168.13.153:1028/v1
DASHSCOPE_BASE_URL_COMPLEX=http://192.168.13.153:1028/v1
DASHSCOPE_BASE_URL_SIMPLE=http://192.168.13.153:1028/v1
MODEL_TIER_COMPLEX=qwen3-30b-a3b
MODEL_TIER_SIMPLE=qwen3-30b-a3b
QWEN_TEXT_MODEL=qwen3-30b-a3b

# ============ MinerU + NPU VLM (port 1040) ============
VL_SERVICE_BACKEND=mineru
MINERU_BACKEND=http-client
MINERU_VL_SERVER=http://192.168.13.153:1040/v1
VL_SERVICE_FALLBACK_TO_QWEN=false

# ============ 应用 ============
HOST=0.0.0.0
PORT=8000
DEBUG=true
```

> 也可以用模板：`cp deploy/env-local.template backend/.env`，模板中 `SERVER_IP` 需替换为 `192.168.13.153`。

## 四、麒麟笔记本 — 启动应用

### 4.1 连接诊断（推荐先跑一次）

```bash
cd ~/project/localknowledgebase-word
chmod +x deploy/fix-connection.sh
./deploy/fix-connection.sh          # 诊断网络、端口、防火墙、.env 配置
./deploy/fix-connection.sh fix      # 诊断 + 自动修复防火墙
```

### 4.2 启动后端

```bash
cd ~/project/localknowledgebase-word
./start-all.sh           # 自动检查网络、模型、清理端口、启动后端
```

启动后终端会显示连接检查结果：

```
==================================================
  Model Server Connectivity Check
==================================================
  LLM  (http://192.168.13.153:1028/v1): OK
  VLM  (http://192.168.13.153:1040/v1): OK
==================================================
```

也可以只检查不启动：
```bash
./start-all.sh check
```

### 4.3 启动前端

另开终端：
```bash
cd ~/project/localknowledgebase-word/frontend
npm run dev
```

### 4.4 访问系统

浏览器打开 `http://192.168.13.101:3000`

```
  → MinerU http-client → MindIE VLM (NPU chips 0-1, port 1040): VLM 推理

  → FastAPI 后端 → OpenAI SDK → MindIE LLM (NPU chips 4-7, port 1028)
```

## 常见问题

**Q: 后端启动显示 LLM/VLM FAILED？**

按顺序检查：
1. `ping 192.168.13.153` — 网络是否通
2. 跑 `./deploy/fix-connection.sh` — 自动诊断并给出修复建议
3. 最常见原因：**服务器防火墙** — 见 2.5 节
4. 容器是否在跑：`ssh root@192.168.13.153 'docker ps'`

**Q: 模型启动后接口不响应？**

权重加载需要时间（30B 约 5-8 分钟，VLM 约 2-3 分钟）。用 `./run-*.sh logs` 查看日志，等 "Daemon start success!" 出现。

**Q: docker load 失败？**

确认镜像文件完整：`ls -lh ~/mindie-image.tar`（应约 18GB）。磁盘空间：`df -h`。

**Q: 启动报错 `type must be boolean, but is null`？**

说明配置文件中缺少 MindIE 必填字段。当前脚本采用「patch 默认配置」策略，会保留容器内默认 config.json 的所有字段。确认使用的是最新版脚本（包含 `python3 -c` patch 逻辑）。

**Q: MinerU PDF 解析很慢？**

确认 `.env` 配置正确：
- `MINERU_BACKEND=http-client`（不是 `transformers`）
- `MINERU_VL_SERVER=http://192.168.13.153:1040/v1`（指向 NPU VLM）
如果仍是 `transformers`，MinerU 会在 CPU 上跑 VLM，非常慢。
