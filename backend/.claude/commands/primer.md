# Prime Context - 项目深度分析命令

对指定目录进行全面深度分析，辅助理解项目结构和问题。

## 使用方式

```
/primer <目录路径> [关注点]
```

示例:
- `/primer backend/app/tools` - 分析tools目录
- `/primer backend/app/services PDF处理流程` - 分析services目录的PDF处理
- `/primer backend/app/api` - 分析API端点

## 执行步骤

### 1. 目录扫描
首先扫描目标目录，找出所有相关文件：
```
使用 Glob 工具找出所有 .py 文件
列出文件数量和目录结构
```

### 2. 关键词搜索
根据用户指定的关注点或默认关键词进行搜索：
- 核心类定义（识别核心组件）
- async def / def（识别核心功能）
- import / from（识别依赖关系）
- router / APIRouter（识别API端点）
- config / CONFIG（识别配置项）

### 3. 代码读取
**重要： 不限制读取文件数量**
根据搜索结果， 逐个读取所有相关文件的完整内容：
- 类定义和实现
- 函数签名和逻辑
- 导入语句
- 配置项

### 4. 流程梳理
根据分析结果，梳理出：
- 完整调用链路图
- 数据流向
- 模块依赖关系
- 入口和出口

### 5. 问题诊断
识别潜在问题:
- 导入错误（文件不存在、模块缺失）
- 配置不一致
- 代码逻辑问题
- 类型不匹配
- 方法调用错误

### 6. 输出报告
输出结构化报告，包含:
- 目录结构概览
- 关键文件清单及用途
- 完整调用流程图
- 发现的问题及位置
- 修复建议

## 报告格式

```markdown
# 一、目录结构
<列出扫描到的目录和文件数量>

# 二、文件清单
| 文件路径 | 大小 | 主要功能 |
|---------|------|----------|
| <file1> | <size> | <description> |
...

# 三、调用流程
<完整调用链路图或文字描述>

# 四、关键文件详细分析
<每个关键文件的详细分析>

# 五、发现的问题
| 问题 | 位置 | 严重程度 | 建议 |
|------|------|----------|------|

# 六、总结
<整体评估和建议>
```

## 约束

1. **不限制读取文件数量** - 用户要求全面分析时，必须读取所有相关文件
2. **必须给出代码位置** - 报告问题时要指出具体文件和行号
3. **流程图必须完整** - 从入口到出口的完整调用链
4. **问题必须可操作** - 给出具体的修复建议，不是泛泛而谈
5. **使用中文输出** - 所有报告使用中文

## 关键词优先级
当用户没有指定关注点时，按以下优先级搜索：
1. class 定义（识别核心组件）
2. async def / def（识别核心功能）
3. import / from（识别依赖关系）
4. router / APIRouter（识别API端点）
5. config / CONFIG（识别配置项）
