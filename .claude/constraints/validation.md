# 验证策略（减少重复生成）

> 目的：避免无限循环优化，提高验证效率

## 首次验证流程

```
┌─────────────────┐
│  静态分析优先   │  ESLint/TypeScript（不运行代码）
└────────┬────────┘
         ↓
┌─────────────────┐
│  单元测试聚焦   │  只测修改的函数（隔离测试）
└────────┬────────┘
         ↓
┌─────────────────┐
│  集成验证       │  关键路径测试
└─────────────────┘
```

## 失败处理规范

### 必须
- 定位到具体错误行号
- 分析根本原因
- 只修改错误部分

### 禁止
- 未定位就重新生成整个文件
- 无差别重写相关代码
- 盲目增加 try-catch

### 策略
```markdown
1. 分析错误信息 → 确定影响范围
2. 定位到具体代码行
3. 最小化修改原则
4. 保持其他代码不变
5. 重新测试验证
```

## 成功标准

| 状态 | 条件 |
|------|------|
| ✅ 通过 | 测试通过 |
| ✅ 可接受 | 人工确认"已知问题，后续修复" |
| ⚠️ 需关注 | 非关键路径失败，记录待办 |
| ❌ 失败 | 核心功能失败，必须修复 |

## 禁止行为

```yaml
禁止:
  - 追求完美导致无限循环
  - 同一错误重复修复超过3次
  - 为通过测试而硬编码
  - 修改无关代码"顺便优化"
```

## 验证检查清单

```markdown
- [ ] 错误已定位到具体行号
- [ ] 修改范围最小化
- [ ] 未引入新依赖
- [ ] 测试覆盖修改部分
- [ ] 无回归问题
```
